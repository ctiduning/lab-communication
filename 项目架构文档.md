## 一、项目概述

### 1.1 业务背景

青岛华测食品检测实验室内部存在以下沟通场景：
- **业务端（销售/客服）** 需要向 **实验室端（检测组）** 发起各类沟通需求
- 沟通类型包括：付费加急、免费加急、数据质疑、跟单、咨询、不合格沟通、数据确认等
- 实验室内部按 **三级部门架构** 组织：一级(业务/实验室) → 二级(产品线/具体实验室) → 三级(检测组)
- 需要支持多人接收、状态跟踪、撤回、完结等完整流程

### 1.2 核心功能矩阵

| 功能模块 | 子功能 | 涉及角色 |
|---------|--------|---------|
| 用户认证 | 邮箱密码登录、记住我、session持久化 | 全部 |
| 通讯录 | 按部门分组、搜索、多选快捷发起 | 全部 |
| 发起沟通 | 填写表单、三级部门筛选、拼音搜索选人、部门名片 | 业务/实验室 |
| 接收消息 | 4状态标签页、快捷回复、红旗标记 | 业务/实验室 |
| 已发送消息 | 7种状态筛选、撤回(5分钟)、完结标记 | 全部 |
| 通知公告 | 发布/编辑/删除、已读统计、点赞点踩 | 管理员 |
| 管理员控制台 | 用户CRUD、Excel导入、统计图表、数据备份 | 管理员 |
| 个人设置 | 修改部门信息、修改密码 | 全部 |

### 2.3 后端 BaaS：Supabase

**版本**：`@supabase/supabase-js@^2.107.0`

使用 Supabase 的四个核心服务：

| 服务 | 用途 | 关键方法 |
|------|------|---------|
| **Auth** | 用户认证、Session管理 | `signInWithPassword()`, `signOut()`, `getSession()`, `getUser()` |
| **Database** | 所有业务数据存储 | `.from('profiles').select('*')`, `.insert()`, `.update()`, `.delete()` |
| **Storage** | 图片附件存储 | `.storage.from('attachments').upload()`, `.getPublicUrl()` |
| **Realtime** | 实时数据更新（未使用完全） | `channel('*').on('postgres_changes', ...)` |

关键配置：
```javascript
// src/utils/supabase.js
import { createClient } from '@supabase/supabase-js'

const supabaseUrl = import.meta.env.VITE_SUPABASE_URL
const supabaseKey = import.meta.env.VITE_SUPABASE_ANON_KEY

export const supabase = createClient(supabaseUrl, supabaseKey)
```

**重要注意事项**：
1. **`.order()` 不能链式调用多次**：`supabase.from('profiles').select('*').order('role').order('department').order('name')` 会产生 400 错误。应改为单个 `.order('name')`。
2. **`.eq('is_disabled', false)` 需确保字段存在**：如果 `profiles` 表没有 `is_disabled` 列，查询会报错。
3. **字段名用 snake_case**：Supabase 表字段是 `department_level3` 而非 `departmentLevel3`。
4. **RLS 策略**：所有表需要配置合适的 RLS 策略，否则查询会返回空或报错。

### 4.2 建表 SQL

```sql
-- ============================================
-- 1. profiles — 用户档案表
-- ============================================
CREATE TABLE public.profiles (
  id UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  username TEXT UNIQUE,
  name TEXT NOT NULL,
  employee_id TEXT,
  role TEXT,                              -- 角色：'business' / '检测组长' / '检测工程师' 等

  email TEXT,
  region TEXT,                            -- 属地（兼容旧数据）

  is_system BOOLEAN DEFAULT false,        -- 是否为系统用户

  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()

-- 索引
CREATE INDEX idx_profiles_role ON profiles(role);
CREATE INDEX idx_profiles_department_level3 ON profiles(department_level3);

-- ============================================

  vip TEXT,                               -- 'yes' / 'no'

  sample_code TEXT,
  sample_matrix TEXT,
  sample_count TEXT,
```

### 4.3 数据库触发器

```sql
-- ============================================
-- 触发器：用户注册后自动创建 profiles 记录
-- ============================================
CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS TRIGGER
LANGUAGE plpgsql
SECURITY DEFINER SET search_path = ''
AS $$
BEGIN
  INSERT INTO public.profiles (
    id, email, name, role, username, employee_id, phone,
    department_level1, department_level2, department_level3
  ) VALUES (
    NEW.id,
    NEW.email,
    COALESCE(NEW.raw_user_meta_data->>'name', split_part(NEW.email, '@', 1)),
    COALESCE(NEW.raw_user_meta_data->>'role', 'business'),
    COALESCE(NEW.raw_user_meta_data->>'username', ''),
    COALESCE(NEW.raw_user_meta_data->>'employee_id', ''),
    COALESCE(NEW.raw_user_meta_data->>'phone', ''),
    COALESCE(NEW.raw_user_meta_data->>'department_level1', ''),
    COALESCE(NEW.raw_user_meta_data->>'department_level2', ''),
    COALESCE(NEW.raw_user_meta_data->>'department_level3', '')
  );
  RETURN NEW;
END;
$$;

-- 绑定触发器
CREATE OR REPLACE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW
  EXECUTE FUNCTION public.handle_new_user();
```

### 4.4 RLS 策略配置

```sql
-- 启用 RLS
ALTER TABLE profiles ENABLE ROW LEVEL SECURITY;
ALTER TABLE communications ENABLE ROW LEVEL SECURITY;
ALTER TABLE communication_recipients ENABLE ROW LEVEL SECURITY;
ALTER TABLE announcements ENABLE ROW LEVEL SECURITY;
ALTER TABLE announcement_reads ENABLE ROW LEVEL SECURITY;
ALTER TABLE notifications ENABLE ROW LEVEL SECURITY;
ALTER TABLE reactions ENABLE ROW LEVEL SECURITY;
ALTER TABLE admin_logs ENABLE ROW LEVEL SECURITY;

-- profiles：所有登录用户可读，仅自己可更新
CREATE POLICY "profiles_select" ON profiles FOR SELECT TO authenticated USING (true);
CREATE POLICY "profiles_update" ON profiles FOR UPDATE TO authenticated USING (id = auth.uid());

-- communications：发送人或接收人可读，发送人可插入
CREATE POLICY "comm_select" ON communications FOR SELECT TO authenticated
  USING (sender_id = auth.uid() OR id IN (
    SELECT communication_id FROM communication_recipients WHERE recipient_id = auth.uid()
  ));
CREATE POLICY "comm_insert" ON communications FOR INSERT TO authenticated
  WITH CHECK (sender_id = auth.uid());

-- communication_recipients：本人相关的可读写
CREATE POLICY "recipients_select" ON communication_recipients FOR SELECT TO authenticated
  USING (recipient_id = auth.uid() OR communication_id IN (
    SELECT id FROM communications WHERE sender_id = auth.uid()
  ));
CREATE POLICY "recipients_update" ON communication_recipients FOR UPDATE TO authenticated
  USING (recipient_id = auth.uid());
```

```javascript
import { supabase } from '../utils/supabase'

const routes = [
  { path: '/login', name: 'Login', component: () => import('../pages/Login.vue') },
  { path: '/', name: 'Home', component: () => import('../pages/Home.vue'), meta: { requiresAuth: true } },
  { path: '/admin', name: 'Admin', component: () => import('../pages/Admin.vue'), meta: { requiresAuth: true } },
  { path: '/announcements', name: 'Announcements', component: () => import('../pages/Announcements.vue'), meta: { requiresAuth: true } },
  { path: '/profile', name: 'Profile', component: () => import('../pages/Profile.vue'), meta: { requiresAuth: true } },
  { path: '/history', name: 'History', component: () => import('../pages/History.vue'), meta: { requiresAuth: true } },
  { path: '/business-initiate', name: 'BusinessInitiate', component: () => import('../pages/BusinessInitiate.vue'), meta: { requiresAuth: true } },
  { path: '/lab-initiate', name: 'LabInitiate', component: () => import('../pages/LabInitiate.vue'), meta: { requiresAuth: true } },
  { path: '/:pathMatch(.*)*', redirect: '/' }  // 兜底：未匹配路由跳转首页
]

const router = createRouter({
  history: createWebHashHistory(),
  routes
})

// 导航守卫：校验 Supabase session
router.beforeEach(async (to, from, next) => {
  const { data: { session } } = await supabase.auth.getSession()
  const isAuthenticated = !!session
  
  if (to.meta.requiresAuth && !isAuthenticated) {
    // 清除所有缓存
    localStorage.removeItem('token')
    localStorage.removeItem('user')
    localStorage.removeItem('sb-qgoqhjwekairknkuqisi-auth-token')
    next('/login')
    return
  }
  
  if (to.path === '/login' && isAuthenticated) {
    next('/')
    return
  }
  
  next()
})
```

### 5.2 路由设计说明

- **Hash 模式**：使用 `createWebHashHistory()` 而非 History 模式，因为部署在 GitHub Pages 子路径下，Hash 模式不需要服务端路由配置。
- **懒加载**：所有页面组件使用动态 `import()`，Vite 会自动代码分割。
- **导航守卫**：每次路由切换都检查 Supabase session，确保认证状态实时有效。
- **缓存清理**：未认证时清除 localStorage 中的 Supabase token。

### 6.4 关键数据流

#### 发起沟通流
```
用户填写表单 → 选择接收人 → 点击发送
  → communicationAPI.create({
      type, vip, customerName, sampleCode, ...,
      recipients: [id1, id2, ...],
      attachments: [{url, name, path}]
    })
  → 1. supabase.from('communications').insert({sender_id, type, ...})
  → 2. supabase.from('communication_recipients').insert([
       {communication_id, recipient_id: id1},
       {communication_id, recipient_id: id2}
     ])
  → 3. supabase.from('notifications').insert([
       {user_id: id1, communication_id, type, content},
       {user_id: id2, communication_id, type, content}
     ])
  → 成功提示 → 跳转首页
```

#### 接收消息流
```
用户点击"接收消息"
  → communicationAPI.getPendingCount(authUser.id)
  → 查询 communication_recipients
    WHERE recipient_id = authUser.id
    AND status = 'pending'
    AND is_recalled = false
    AND communication_id IN (
      SELECT id FROM communications
      WHERE is_recalled = false AND is_system_notification = false
    )
  → 显示待处理数量徽标

用户点击回复（同意/拒绝/等我确认）
  → communicationAPI.createReply(communicationId, {content})
  → supabase.from('communication_recipients')
      .update({status: 'replied', reply, reply_content, replied_at})
      .eq('communication_id', communicationId)
      .eq('recipient_id', authUser.id)
```

#### 撤回流
```
用户在"已发送消息"中点击撤回
  → communicationAPI.recallMessage(communicationId)
  → 检查创建时间是否在5分钟内
  → supabase.from('communications')
      .update({is_recalled: true, recalled_at: now()})
      .eq('id', communicationId)
  → supabase.from('communication_recipients')
      .update({is_recalled: true})
      .eq('communication_id', communicationId)
  → 为所有接收人创建系统通知
  → 成功提示

撤回后编辑重发
  → localStorage.setItem('recalledMessageEdit', JSON.stringify(editData))
  → 跳转发起沟通页面
  → onMounted 检测 localStorage 数据自动填充
```

#### 管理员导入用户流
```
管理员上传 CSV → 读取数据
  → 逐行调用 authAPI.register({
      username, password: 'Ct1@2026',
      name, role, employeeId, phone, email,
      departmentLevel1, departmentLevel2, departmentLevel3
    })
  → 调用 supabase.rpc('admin_create_user', { ... })
  → 触发器 handle_new_user() 自动创建 profile
  → 记录导入结果（成功/失败）
```

```javascript
  const elapsed = Date.now() - new Date(msg.created_at).getTime()
  return !msg.is_recalled && elapsed < fiveMinutes
}
```

## 十一、关键算法与工具函数

### 11.1 拼音搜索算法

```javascript
// src/utils/pinyinSearch.js
import { pinyin } from 'pinyin-pro'

// 为用户预计算所有搜索关键词
export function buildSearchKeys(user, roleNameMap = {}) {
  const name = user.name || ''
  const dept = user.department || ''
  const roleName = roleNameMap[user.role] || user.role || ''

  return {
    ...user,
    _searchKeys: {
      name,
      nameLower: name.toLowerCase(),
      pinyinInitial: pinyin(name, { pattern: 'first' }).toLowerCase().replace(/\s/g, ''),
      pinyinFull: pinyin(name, { pattern: 'pinyin' }).toLowerCase().replace(/\s/g, ''),
      deptLower: (dept || '').toLowerCase(),
      deptPinyinInitial: pinyin(dept, { pattern: 'first' }).toLowerCase().replace(/\s/g, ''),
      deptPinyinFull: pinyin(dept, { pattern: 'pinyin' }).toLowerCase().replace(/\s/g, ''),
      roleName,
      roleNameLower: roleName.toLowerCase(),
      rolePinyinInitial: pinyin(roleName, { pattern: 'first' }).toLowerCase().replace(/\s/g, ''),
      rolePinyinFull: pinyin(roleName, { pattern: 'pinyin' }).toLowerCase().replace(/\s/g, ''),
    }
  }
}

// 匹配逻辑：中文包含 > 拼音首字母前缀 > 拼音全拼前缀 > 拼音全拼包含
export function matchUser(query, searchKeys) {
  if (!query) return true
  const q = query.trim().toLowerCase()
  if (!q) return true
  const s = searchKeys

  if (s.nameLower.includes(q)) return true
  if (s.deptLower.includes(q)) return true
  if (s.roleNameLower.includes(q)) return true
  if (s.pinyinInitial.startsWith(q)) return true
  if (s.deptPinyinInitial.startsWith(q)) return true
  if (s.rolePinyinInitial.startsWith(q)) return true
  if (s.pinyinFull.startsWith(q)) return true
  if (s.deptPinyinFull.startsWith(q)) return true
  if (s.rolePinyinFull.startsWith(q)) return true
  if (s.pinyinFull.includes(q)) return true
  if (s.deptPinyinFull.includes(q)) return true

  return false
}
```

## 十五、常见问题与排错

### 15.1 部署后页面空白

**症状**：访问 GitHub Pages 地址，页面完全空白，Console 显示 404  
**原因**：部署时错误地将开发环境的 `index.html`（引用 `/src/main.js`）推到了 gh-pages  
**修复**：
```bash
# 只部署 dist/ 内容
git checkout --orphan gh-pages-clean
git rm -rf .
xcopy /e dist\* .
git add . && git commit -m "deploy"
git push -f origin gh-pages-clean:gh-pages
git checkout main && git branch -D gh-pages-clean
```

### 15.2 通讯录不显示数据

**症状**：Organization.vue 中没有任何人员显示  
**原因**：`loadUsers()` 中多个 `.order()` 链式调用导致 400 错误  
**修复**：改为单个 `.order('name')`

### 15.3 消息接收人重复显示

**症状**：BusinessInitiate.vue 下拉框中同一人出现两次  
**原因**：`ROLE_OPTIONS` 中包含中英文两种角色值，导致相同的 label 在 `roleOrder` 中出现两次  
**修复**：在 `recipientGroups` 计算中使用 Map 去重

### 15.4 业务端不显示属地 / 实验室端不显示检测组

**症状**：通讯录中分组不正确  
**原因**：分组使用了旧的 `region` 和 `department` 字段，而非 `department_level3`  
**修复**：
```javascript
const region = u.department_level3 || u.department_level2 || u.department_level1 || '未分配属地'
const dept = u.department_level3 || u.department_level2 || u.department_level1 || '未分配检测组'
```

### 15.5 Element Plus 类型弃用警告

**症状**：Console 显示 `[props] [API] type.text is about to be deprecated`  
**原因**：`<el-button type="text">` 已弃用  
**修复**：改为 `<el-button text>`

### 15.6 无法连接 GitHub

**症状**：`git push` 超时  
**原因**：网络限制（公司网络/防火墙）  
**解决**：切换网络环境（手机热点）、配置代理、或在网络正常情况下重试
